# Choreia システム

システム販売の案件管理。プロダクトごとに提案先とフェーズを横に並べて一覧し、営業が聞き取った要件(ヒアリング票)を開発へ渡す。人財(Jinzai)とは別のアプリ。

**本番:** https://choreia.github.io/Pipeline/

## 構成
[Choreia 人財](https://github.com/Choreia/Jinzai) と同じ作り。

| 要素 | 技術 |
|------|------|
| フロントエンド | 単一 HTML（ビルド不要） |
| 認証 | Google OAuth 2.0（組織ドメインのみ・フリーメール不可） |
| データ保存 | Google Sheets API v4（初回セットアップで自動作成） |
| ホスティング | GitHub Pages |

## 画面
- **パイプライン**: プロダクトの行の右に案件（提案先とフェーズ）を横に並べる。30日以上更新のない案件は黄色
- **フェーズ集計**: プロダクト×フェーズの件数（月1回の定例で使う）
- **プロダクト**: 種類（プロダクト／個別開発）、誰が売るか（安河内で完結／VB営業／M2営業）、価格
- **ヒアリング**: 営業がお客様に聞く固定14項目(誰が使う／今どうやっている／困りごと／入力／出力／件数と頻度／つなぐ先／環境／期限／予算感／決裁者／成功の条件／制約／資料)。案件ごとに1枚、埋まり率を%で表示。途中保存でき、「開発へ渡す」で状態が変わり案件の履歴にも残る。「AI用にコピー」でMarkdownを取り出し、要件定義のたたき台にする
- **訪問記録**: ボイスメモ・Google Meet 議事録のリンクを残す

フェーズ: 構想 / 提案予定 / 提案中 / 試験導入 / 受注 / 運用中 / 失注

## シート構成（初回セットアップで自動作成）
プロダクト / 案件 / 訪問記録 / ヒアリング。ID体系: PRD- / DEAL- / LOG- / HEAR-。既存のスプレッドシートに無いシートは起動時に自動で足す。

## 初期データ
取引先名や金額を含むため、このリポジトリには置かない。
共有ドライブに置いた `choreia-pipeline-seed.json` を、管理者が ⚙ 設定 の「初期データを入れる」で読み込む（シートが空のときだけ）。
